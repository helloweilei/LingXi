## 重构：章节摘要 → 章节大纲（写前规划）
用户要求把刚做的「章节摘要（写后总结）」改为「章节大纲（写前规划）」，并改造自动创作流水线为「先生成大纲、再按大纲写正文」，避免收尾失控。本次为彻底概念重构 + 全量改名：

- **数据库**：新增 `V8__chapter_outline.sql`——`chapter_summaries` 重命名为 `chapter_outlines`，列 `summary` 重命名为 `outline`（兼容 H2 MODE=MySQL 与 MySQL 8 的 `RENAME COLUMN`）。删除了旧 `ChapterSummary.java` / `ChapterSummaryRepository.java`。
- **重命名链路**（后端）：`ChapterOutline` 实体 + `ChapterOutlineRepository`；`MemoryDtos` 的 `OutlineVO/OutlineItemVO/OutlineReq`；`MemoryService` 的 `outlines/generate/saveOutline/deleteOutline`；`MemoryController` 端点 `summaries`→`outlines`（GET/POST generate/PUT/DELETE 全部 `/outlines`）。
- **AI 层**：`AiTaskType` 移除 `SUMMARIZE`、新增 `CHAPTER_OUTLINE`；`AiService.summarize`→`generateChapterOutline`（prompt 改为产出章节规划：场景节拍/关键进展/人物弧光/收尾钩子），并 `saveOutline`；`writeChapter` 在写正文前注入【本章大纲】段（若有），让 AI 严格按规划施工；`ContextBuilder.buildSummaries`→`buildOutlines`（段标签「已规划章节大纲」，`maxRecentOutlines`）；`AiController` 的 summarize 端点改为 `/chapters/{chapterId}/outline`。Mock 引擎 `chapterOutline(ctx)` 返回示例大纲。
- **自动创作流水线**（`AutoWriteService`）：删除「写后生成摘要」，改为「写前 `generateChapterOutline` → `writeChapter` 按大纲写正文」；`Params.autoSummary`→`autoOutline`（默认 true）；`WritingTaskDtos.AutoWriteReq/TaskVO` 同步；`NovelService` 仓库更名；`remove` 清理大纲。
- **前端**：`api/types.ts` 的 `ChapterOutlineItem(hasOutline/outline)`、`WritingTaskVO.autoOutline`；`api/index.ts` 的 `outlineApi`（端点 `/outlines`）+ `AutoWriteReq.autoOutline`；`NovelDetail.tsx` 的 `OutlineTab`（Tab 标签「章节大纲」，文案改为写前规划）/ 删除 `summaryApi`/`ChapterSummaryItem`/`autoSummary` 全部引用；`AutoWritePanel` 的 `autoOutline` 字段与标签「生成章节大纲（写作前规划）」。
- **测试同步**：`AutoWriteTaskTest`（`back.autoOutline()`）、`ContextBuilderTest`（`ChapterOutline`/`setOutline`/`章大纲内容`）。
- 验证：前端 `npm run build`（tsc + vite）通过；后端本环境无 Maven 未编译，已全量核对引用无残留（`ChapterSummary/summary/SUMMARIZE/autoSummary` 等均无匹配）。本地需 `mvn test` 验证（含 Mock 零 Key 演示）。
- 注意：既有 DB 已跑过 V7（存在 `chapter_summaries`），V8 迁移负责表/列改名；若 DB 已存在 `chapter_outlines`（异常态）则 V8 会失败，属预期的升级路径。
