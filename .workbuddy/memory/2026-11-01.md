## 修复：NovelDetail 头部重复 React key 警告
- 现象：生成章节大纲成功后控制台报「two children with the same key `0`」。
- 根因：`NovelDetail.tsx` 头部 `Space` 容器下题材 Tags 与语言风格 Tags 两组兄弟元素都用 `key={i}`（都从 0 起），同时非空即冲突；生成大纲成功后 novel 重载触发重渲染才显现。
- 修复：key 改为 `genre-${i}` / `style-${i}` 前缀区分。
- 验证：前端 tsc + vite build 通过。
- 教训：同一父容器下多组 `.map()` 渲染时，数字索引 key 必须加业务前缀。

## 修复：大纲生成后表格跳回第一页
- 根因：NovelOutlinesTab 大纲表用 `{loading ? <Spin/> : items.length===0 ? <Empty/> : <Table/>}` 条件渲染——load() 期间 Table 被 Spin 卸载、加载完重新挂载，antd Table 内部分页状态（当前页）清零。
- 修复：改为仅在「首次加载且无数据」时显示 Spin；一旦有数据 Table 常驻挂载，加载态改用 Table 自带 loading 遮罩（`loading={loading}`）。
- 教训：需要保留分页页码/滚动位置等组件内部状态的表格，绝不能用条件渲染在 loading 时卸载重建。
