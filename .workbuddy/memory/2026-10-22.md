# 2026-10-22

## 修复：一键生成的章节大纲不带完结规划（与全书大纲脱节）

**根因**（`AiService.generateChapterOutline`）：
1. prompt 只用 `contextBuilder.buildNovelInfo(novel)`（仅作品信息），**全书大纲 `novel.outline` 从未进 prompt**，却要求模型"与全书大纲方向一致"——模型看不到结局描述；
2. 无终章识别，最后一章按普通章节生成（还要求"为下一章留钩子"）。

**修复**：
- `AiService.generateChapterOutline` 增加重载 `(novelId, outlineId, user, totalChapters)`；prompt 新增【全书大纲】段（`tail(outline, 2500)`，取尾部保住结局描述）；
- 终章判定 `isFinalPlannedChapter(outline, total)`：显式总数优先，否则按规划行数推断；终章追加【完结规划（最高优先级）】指令块（收束主线/悬念答案/人物归宿/严禁下一章钩子），任务第 4 条钩子规则改为"若不是终章才留钩子"；
- prompt 组装抽为包级 `buildChapterOutlinePrompt(...)` 便于单测；
- `AutoWriteService` 第 215 行显式传 `p.chapters`（流水线边建行边生成，行数无法识别终章）；
- 新增回归测试 `AiServiceChapterOutlinePromptTest`（4 例）。

**顺手修复的存量失败测试**（均与本次 bug 无关，修复前 `mvn test` 编译/运行即红）：
- `ContextBuilderTest` 调用已改名的 `getMaxRecentOutlines()` → `getMaxRecentSummaries()`（测试套件原本编译不过）；
- `MockLlmClient.chapterOutline`：5 个 `%s` 只传 1 个参数，mock 引擎每次生成章节大纲必崩 → 改 `%1$s`；
- `AiService.normalizeTitle`：`^第\d+章` 不匹配中文数字/回卷（"第一章：xxx"剥不掉）→ 正则扩展 `[\d〇零一二三四五六七八九十百千万]+[章回节卷]`；
- `FlywayMigrationTest`：V8 已把 `chapter_summaries` 更名 `chapter_outlines`，测试期望滞后 → 更新；
- `IdeaGuideTargetWordsTest.plainNumberIsTakenAsWords`：字数下限 1 万的收敛未反映到期望 → 更新为 15000 字/8000 字两例。
