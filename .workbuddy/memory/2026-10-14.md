## 修复2：landChapter 三元表达式类型不兼容（VO vs 实体）
现象：IDEA 报「不兼容的类型: 条件表达式中的类型错误」，指向 AiService:349-351。

根因：`chapterService.save(...)` 和 `chapterService.createAtOrder(...)` 返回的都是
**`ChapterDtos.VO`（record 视图对象）**，不是 `Chapter` 实体。
我写成 `Chapter chapter = (byOrder != null) ? ...VO... : ...VO...;` → 左边声明实体、右边给 DTO。

修复：
```java
Long chapterId = (byOrder != null)
        ? chapterService.save(...).id()
        : chapterService.createAtOrder(...).id();
Chapter chapter = chapterRepository.findById(chapterId).orElseThrow();
```
顺带修的问题：
- `outline.getChapterOrder()` 是 Integer，`createAtOrder`/`findFirstBy...` 收 int，
  直接传会自动拆箱 NPE → 统一先算 `int order = getChapterOrder() == null ? 1 : getChapterOrder()` 再传
- `AutoWriteService.ensureOutlineRow(novelId, chapterOrder, user)` 的 `user` 从未使用 → 去掉参数
- `resolveChapterIdByOutline` 的 `novelId` 闲置 → 改为真正做属主校验 `.filter(o -> o.getNovelId().equals(novelId))`

全仓扫描确认：`Entity var = xxxService.loadOwned/findById(...)` 这类共 39 处全部正确
（loadOwned/findById 返回实体），无其它 VO/实体混用。

**教训（项目约定）**：
本项目 Service 层有两种返回风格，改动时务必看清：
- `loadOwned / findById / repository.find*` → 返回**实体**，可直接当 `Chapter`/`Novel` 用
- `create / save / get / list / versions` → 返回 **record VO**（ChapterDtos.VO 等），需 `.id()` 取 id
三元表达式尤其容易踩：两边若一个是实体一个是 VO，报错信息还可能指向另一行。

## 三、标题编辑主场迁移到章节大纲（单向同步）
需求：把标题编辑功能移到章节大纲页；生成正文后直接同步标题；
章节内容页保留改名能力，但两者**不打包、不双向同步**。

### 权责划分（本次确立，重要）
- **章节大纲页 = 标题主场**：点标题即可行内编辑；生成正文时以大纲标题写入章节
- **章节内容页（Editor）= 局部改动**：改名只影响该章，不回写大纲
- **同步是单向的**：大纲 → 章节。反向不回写，避免两个入口互相覆盖

### 后端（AiService.landChapter）
原实现缺陷：outline.chapterId 已有章节时**直接 return，完全不同步标题**。
改为：
- 新增 `plannedTitle`（规划标题，空则 null）
- 已有章节分支：仅当 `plannedTitle != null && 不等于章节当前标题` 时才同步标题，
  **只改 title、保留正文**（`new SaveReq(plannedTitle, existing.getContent(), null)`）
- 新建分支：标题优先级改为 `规划标题 > 已有章节标题 > 兜底占位名`
（`persistOutlineAndTitle` 里 AI 自动起名的同步逻辑不动：只补占位名、只同步空章节）

### 前端
- `outlineApi.saveTitle(novelId, outlineId, title)`：只传 chapterTitle，
  后端 `saveOutline` 对 null 字段语义是"不改"，因此不会误清大纲内容/字数
- `NovelOutlinesTab`：章节名列由纯文本改为**行内可编辑**
  （editingTitleId/editingTitle/savingTitle 状态 + startEditTitle/commitTitle）
  列宽 150→190，列头 tooltip 讲清权责；未命名时显示「第N章（未命名）」灰字
- `Editor.tsx`：保留改名能力，标题输入框加 Tooltip 说明
  「只影响本章，不回写大纲；重新生成正文时以大纲名为准」

**产品原则**：同一字段可有多个编辑入口，但必须明确"谁是主场"，
且同步方向单一（上游→下游）。双向同步必然产生"我明明改了怎么又被覆盖"的困惑。
- NovelOutlinesTab：章节名/预计字数改为点击编辑图标进入行内编辑（图标+Tooltip 提示可编辑，降低发现成本）；长章节名省略显示，Tooltip 展示全文，不再溢出。前端 build 通过。
