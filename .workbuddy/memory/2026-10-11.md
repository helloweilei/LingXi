## 十三、修复 SSE 完成后永久"生成中"（重要，影响所有流式场景）
现象：正文已生成完、SSE 已收到 done 事件，但弹窗一直显示"正在生成中，请勿关闭"。

根因（`frontend/src/api/ai.ts` 的 streamSse）：
1. 原循环 `for(;;) { const {done} = await reader.read(); if (done) break; ... }`
   **只在服务端关闭连接时退出**；收到 `event: done` 仅调用 onDone 回调，不终止循环。
   Nginx/网关常保持 SSE 连接（X-Accel-Buffering 等），导致 await 长期挂起，
   调用方 `finally`（setWriteOpen(false) / setGenerating(false)）永不执行 → 永久 loading。
2. 附带缺陷：SSE 的 `event: error` 只是报文，不会让 fetch reject，
   调用方 try/catch 收不到错误，还会继续提示"生成成功"。

修复（api/ai.ts 一次性覆盖全部 7 处调用）：
- 引入 `finished` 标志；handleEvent 收到 done/error 时置 true
- 循环条件改为 `while (!finished)`；try/finally 中 finished 时 `await reader.cancel()` + releaseLock()，
  既能及时结束又避免 reader/连接泄漏
- 引入 `streamError`；error 事件记录后，函数结束前 `throw new Error(streamError)`，
  让调用方 catch 正常捕获（否则失败也报成功）
- 调用点配合调整（避免 error 双重提示）：NovelOutlinesTab.writeOne/writeAll、NovelDetail.genCoverPrompt
  移除冗余 onError（改由 catch 统一提示，writeAll 的 catch 会带上"第N 章"前缀）；
  NovelChatTab / AiDrawer 保留 onError（幂等设置错误态，无副作用）

**经验**：SSE 客户端必须以"收到终止事件"为准结束读取，不能依赖连接关闭；
服务端 error 事件要显式转异常，否则 try/catch 是假的安全感。
